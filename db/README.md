# Database

The live schema is built by Flyway from `backend/src/main/resources/db/migration/` every time the backend starts.
The files here are for reading, reviewing and demo data. None of them is run automatically.

| Path | What it is |
|---|---|
| `schema.sql` | The target schema designed before coding (28 tables). LEAD-owned (CLAUDE.md R-02) |
| `marketlink-schema-dump.sql` | `mysqldump --no-data` of the tables the migrations actually create, for comparison with `schema.sql` |
| `seed.sql` | Demo data: 4 markets, 10 approved stalls, 51 products, orders in all 6 statuses, reviews, favourites. Idempotent |
| `seed-extended.sql` | Six months of history on top of `seed.sql`: 10 more stalls with 41 products, 100+ customers, 500+ orders, reviews, chats, feedback. Generated by `scripts/generate-seed.js` (seeded, so a rerun writes the same data); idempotent |
| `seed-images/` | Photos for the 4 markets and the products, copied into the uploads volume by `make seed-images`. `PROMPTS.md` holds the prompt for every photo, including the ones the extended stalls still wait for |

Load the demo data once the stack is up:

```bash
make seed
```

Then, for the dashboards and reports to have history to show, the extended set (all its accounts also use
`Demo@1234`):

```bash
make seed-extended        # production: make prod-seed-extended, after make prod-seed
```

A product of the extended stalls shows its own photo once `seed-images/products/<name>.jpg` exists (names and
prompts in `seed-images/PROMPTS.md`). Until then it shows a photo of the same kind of product, or the category name.
After adding photos: `node scripts/generate-seed.js`, then `make seed-extended` again.

The accounts it creates are listed in [`docs/DEMO_CREDENTIALS.md`](../docs/DEMO_CREDENTIALS.md). A schema change always
goes through a new migration, never an edit to a merged one (CLAUDE.md R-03).
