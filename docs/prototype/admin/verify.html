What the server checks

The password step did not hand out a session. It put a five-minute pending token in Redis, and only a correct code here turns that into the real JWT, so a stolen password alone reaches nothing.

Algorithm
TOTP, RFC 6238 · HMAC-SHA1 · 6 digits · 30-second step
Clock skew
The step before and the step after are accepted
Replay
A used counter is kept in Redis until its step passes, so the same code cannot be sent twice
Rate limit
5 tries, then a 15-minute lock on the account, through the bucket4j-redis already in pom.xml
